# React 前端目录

这里包含 Vite/React 源码、前端测试、构建配置和锁文件。

- 浏览器只能通过 `src/lib/api.ts` 调用 Go API，不能直连 MongoDB 或读取服务端密钥。
- 业务界面放 `src/features/`，应用编排放 `src/app/`，无业务状态组件放
  `src/components/`。
- 依赖变化同时提交 `package.json` 与 `package-lock.json`，不提交 `node_modules/`
  和 `dist/`。
- 页面改动检查加载、空、错误、成功状态，并用 Playwright 验证桌面和 390px 视口。
- 业务行为优先写 Testing Library DOM 测试，纯计算保留单元测试；新增代码不得绕过
  Vitest 覆盖率门槛。不要用只渲染不断言交互结果的测试代替用户路径验证。
- 页面负责数据编排，表单和复杂交互拆成同功能目录下的组件；出现多个独立职责时及时
  拆分，避免继续扩张单个超大页面文件。
- 页面以真实日期为主轴，核心关系固定为 `Day -> ordered Place`，`Segment` 只连接同一
  Day 中的两个 Place；不得从标题、组合日期文本或路线名称推断关联。
- 当日页只聚合当前日资源；地图只请求当前日路线。高德不支持的交通方式必须显示为
  示意连线，不能伪装成驾车道路。
- 新增和编辑统一使用 `EditorSurface`：桌面按复杂度使用弹窗或抽屉，390px 使用底部
  弹层，并保留焦点、未保存确认和页面上下文。
- 日期、日期时间和时分输入统一使用 `TemporalInput`；Day 日期同时展示并执行 Trip
  起止范围，不能只依赖浏览器默认校验气泡。
- 资料只呈现标题、内容、平台、记录人及执行日/地点关联；平台来自
  `platform-type` 标签，执行日和地点筛选保存在 URL 查询参数。
- 移动端一级导航固定为“今天、日程、费用、更多”；当日地图放在“今天”底部，“更多”
  只展开低频页面快捷入口，不跳转到独立页面；旅行实例词汇不得写入通用分类。
- 所有用户可见的标题、按钮、提示、枚举值和错误信息使用中文；英文稳定代码只用于存储
  与接口传输，必须在展示层转译，不得直接泄漏到页面。
- API 变化以模块化 OpenAPI 当前契约为准；成功响应必须有明确类型，不在前端维护第二套
  替代字段或契约之外的资源解析。
- 修改后运行 typecheck、Vitest 覆盖率、build、ESLint 和依赖审计；页面变化还要运行
  Playwright。完成前评估本文件及根规则。
